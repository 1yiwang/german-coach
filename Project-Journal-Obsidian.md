### Architecture & Key Decisions
- **Lumina is a reference, not a dependency.** Lumina is React-Vite-Tauri (desktop) with SQLite + 8 AI providers + eye tracking + Japanese/Sanskrit toolkits. We're Next.js-on-Vercel + Convex + Claude-only. Algorithms and UX patterns port; infrastructure does not. Concretely: we lift `srsService.ts` line-by-line into `lib/srs.ts` (renaming fields, dropping zod, keeping the four-rating shape), but we **don't** copy `Reader.tsx` (68 KB monolith — our per-sentence-card UI is a cleaner fit for the design's "click to expand analyze/practice" interaction).
- **Pre-define the full Convex schema before any wiring.** Cheaper to refine `convex/schema.ts` while it's just a file than after a deploy with real data. v0.1 ships the schema; v0.2 turns it on. Same playbook used in `swiss-job-agent-web`.
- **shadcn Base Nova preset (the `@base-ui/react` backend)**, not the older Radix-based shadcn. This is shadcn's 2026 default — comes with `lib/utils.ts`, oklch CSS variables, `tw-animate-css`, and component primitives that **don't** support `asChild` (cost me one build iteration). Trade-off: more modern + better Tailwind 4 alignment vs. losing the `asChild` Slot pattern → use `buttonVariants` + `<Link className={...}>` instead, which is what the current shadcn docs recommend anyway.
- **Browser-native TTS (`SpeechSynthesisUtterance` with `lang="de-DE"`)** for v0.1 instead of ElevenLabs. Zero cost, ships today, every desktop browser has a German voice. ElevenLabs comes in v0.4 only if the native voice quality proves insufficient.
- **`next@16.2.6` instead of literally Next.js 15.** `create-next-app@latest` shipped 16.2.6 today (released within the last few weeks). All App-Router / Server Component APIs from 15 still work in 16; Turbopack is now default. Sticking with 16 unless something breaks.
- **No `core-standards.mdc` yet.** Now that we have a concrete tech stack (Next.js 16 + Convex + shadcn Base Nova + Claude + Tailwind 4), the next session is the right time to drop one in `.cursor/rules/` with paths and conventions — defer one more day so it can reference the actual file layout.
- **Pivoted Claude → DeepSeek as the v0.2 LLM.** `design.md` originally specified "LLM | Claude API"; user override during this session was "用 DeepSeek (OpenAI 兼容)". Reasoning: cost (DeepSeek is ~1/10 of Claude per token), OpenAI-compatible REST means the client is 200 lines of plain `fetch` (no SDK), and provider migration later is trivial — just swap `DEEPSEEK_BASE_URL` env var. The 4 prompt templates (`analyzePrompt`/`practicePrompt`/`lookupPrompt`/`chatSystemPrompt`) live in `lib/llm.ts` exactly so this swap stays a one-file change.
- **Plain `fetch` instead of the `openai` npm package.** We only need two operations (JSON completion + SSE streaming); the SDK adds ~200 KB and a runtime dependency for zero new behavior. SSE parsing is a 30-line state machine that lives in `chatStream()`.
- **Hand-wrote `convex/_generated/` stubs and committed them.** Convex's normal flow is: run `npx convex dev` interactively (browser login), which writes `_generated/` with type-safe `api` / `internal` proxies. But this turn ran in a non-interactive CLI, so codegen would fail. Two options: (a) gate the whole `/review` migration behind "user runs convex dev later" — sloppy hand-off; (b) hand-write the smallest possible `_generated/` shim using `anyApi` from `convex/server` and proper `FunctionReference<"query"|"mutation", "public", ...>` types per function. Picked (b) so `npm run build` validates **the whole v0.2 wiring**, not just the parts that don't need Convex types. Removed `convex/_generated/` from `.gitignore` so the stubs travel with the repo; once the user runs `npx convex dev`, real codegen overwrites the stubs locally and they commit the diff once.
- **SSR safety for `useQuery`.** Convex's `useQuery` throws if no `ConvexProvider` is mounted above it. At `next build` time (no `NEXT_PUBLIC_CONVEX_URL` yet) the provider deliberately renders a passthrough, so `/` and `/review` would crash during prerender. Fix: mount-guard the affected components (`useState(mounted)` + `useEffect`) and mark `/` as `force-dynamic`. This keeps the rest of the app statically generated and only opts out the two pages that actually need a runtime Convex connection.
- **`/review` writes back to Convex during grading, not after.** Each rating fires `recordReview` immediately and adds the word to a local `reviewedIds` set so the same card doesn't reappear on next refetch. Trade-off: if the network is bad mid-session, the local state shows "done" before Convex confirms — acceptable for a single-user app, would need optimistic-with-rollback for multi-device.
- **`.gitignore` is necessary but not sufficient for secrets.** `.gitignore` protects only the git-push surface; it does nothing about the agent-context surface (Read tool → conversation context → `agent-transcripts/*.jsonl` + model-provider logs). The fix is a project-rule (`.cursor/rules/secrets.mdc`), not a `.gitignore` tweak. This is a generally-applicable insight for any project using an AI coding assistant — should probably land in the upstream `cursor-daily-workflow` template too.
